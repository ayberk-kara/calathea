The stock runtime spent most of its time moving data, not computing it. A
profiler trace pointed straight at attention: the projection, the softmax,
and the weighted sum each round-tripped activations through global memory,
and the KV-cache reallocated on every step.

## Fusing the attention block

Collapsing the three passes into one kernel keeps the working set in shared
memory and registers. Tiles of the score matrix are produced, softmaxed
online, and consumed without ever being written back — the classic
streaming-softmax trick, specialized for our head dimensions.

<Callout label="Rule of thumb:">
  If your arithmetic intensity is below the GPU's ridge point, no amount of
  faster math helps — you are paying for bandwidth. Fuse first, optimize the
  inner loop second.
</Callout>

## Paging the KV-cache

Instead of one contiguous buffer per sequence, the cache is split into
fixed-size pages handed out by a small allocator. Sequences grow without
copying, fragmentation stays bounded, and batching requests with wildly
different lengths stops wasting memory bandwidth.

```rust
// page table lookup, one entry per 16 tokens
let page = kv_pages[seq_id * max_pages + (pos >> 4)];
let slot = page * page_stride + (pos & 15);
```

The result is a serving runtime that's a near drop-in replacement for the
stock pipeline, at 4.1x the throughput and the same latency budget.
